# Secure Service API

Микросервис на Go для регистрации, аутентификации и управления профилями пользователей с использованием СУБД PostgreSQL и авторизации на базе JWT (JSON Web Tokens).

## 🚀 Особенности проекта

* **Безопасность (Zero Password SQLi Protection):** Полная защита от SQL-инъекций благодаря параметризованным SQL-запросам (`EXISTS`, `INSERT INTO ... RETURNING`). Хэш пароля полностью исключен из выборок профиля на уровне СУБД.
* **Передача данных по значению:** Структуры пользователей внутри DTO-ответов передаются по значению, исключая паники (`nil pointer exception`) и оптимизируя работу сборщика мусора (Garbage Collector).
* **Архитектурный Middleware:** Слой авторизации проверяет формат `Bearer <token>` и безопасно изолирует контекст запросов с помощью кастомных типов ключей (`contextKey`).
* **100% Тестовое покрытие:** Интеграционные тесты на Go изолированы от СУБД при помощи пакета `go-sqlmock`.

### Доступные API Эндпоинты:
* `GET  /health` — Проверка здоровья сервиса и пинг базы данных.
* `POST /register` — Регистрация нового аккаунта (возвращает `201 Created` и объект `AuthResponse`).
* `POST /login` — Аутентификация. При любых ошибках выдает скрытный статус `401 Invalid email or password`.
* `GET  /profile` — Получение данных профиля текущего пользователя (доступен только через `AuthMiddleware`).

## ⚙️ Быстрый старт (Локальный запуск)

### 1. Подготовка окружения
Создайте файл **`.env`** в корневой папке проекта и заполните его конфигурационными данными:

```env
SERVER_PORT=8080
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_secure_password
DB_NAME=secure_service
JWT_SECRET=your_jwt_secret_key_here
```

Для генерации JWT_SECRET выполните:
```bash
openssl rand -hex 32
```

### 2. Установка зависимостей
Убедитесь, что модули Go инициализированы, и скачайте пакеты:
```bash
go mod tidy
```

### 3. Автогенерация Swagger документации
Перед запуском скомпилируйте аннотации комментариев в файлы Swagger:
```bash
swag init
```

### 4. Запуск сервера
```bash
go run .
```
После успешного старта интерактивная документация будет доступна по адресу:
🔗 **[http://localhost:8080/swagger/index.html](http://localhost:8080/swagger/index.html)**

## 🐳 Запуск базы данных в Docker (Через Docker Compose)

Если вы хотите разрабатывать и запускать Go-приложение локально, но вам нужна готовая и настроенная база данных PostgreSQL, вы можете поднять её одной командой в Docker.

1. Запустите контейнер СУБД в фоновом режиме:
   ```bash
   docker-compose up -d
   ```

2. Проверьте, что база данных успешно запустилась и проходит проверку здоровья (healthcheck):
   ```bash
   docker-compose ps
   ```
   *Статус контейнера должен быть `up (healthy)`.*

3. Посмотреть логи СУБД в реальном времени (полезно для отладки SQL-запросов):
   ```bash
   docker-compose logs -f postgres_db
   ```

4. Чтобы остановить базу данных и освободить порты:
   ```bash
   docker-compose down
   ```
   *Все сохраненные пользователи и данные не пропадут, так как они надежно изолированы в Docker-томе `pgdata`.*

## 🧪 Запуск автотестов

### Вариант 1: Локальные тесты Go
Интеграционные тесты проверяют всю цепочку работы хендлеров и бизнес-логики без необходимости физического поднятия PostgreSQL за счет использования `sqlmock`:
```bash
go test -v ./...
```

### Вариант 2: Сквозные тесты (E2E) через Postman
1. Импортируйте файл коллекции `secure_service.postman_collection.json` в Postman.
2. Убедитесь, что ваш Go-сервер запущен локально на порту `8080` (или через Docker).
3. Запустите автоматический раннер коллекции (**Run Collection**). Тесты на JavaScript автоматически извлекут JWT-токен из шага авторизации и прокинут его в скрытые заголовки профиля.

## 🔒 Безопасность и Валидация

* **Формат данных:** Имена пользователей (`username`) автоматически валидируются регулярным выражением `^[a-zA-Z0-9_]+$` (только латиница, цифры и знаки подчеркивания). Длина ограничена от 3 до 30 символов для защиты от DOS-атак на базу.
* **Атака перебором:** Приложение защищено от перебора email-адресов. Логика входа возвращает идентичный ответ (`401 Unauthorized` / `Invalid email or password`) как при отсутствии учетной записи, так и при вводе неверного пароля.
* **Маскирование в JSON:** Поле `password_hash` защищено тегом `json:"-"` в структуре `User`, что полностью исключает случайную утечку хэша в HTTP-ответах.
