## Задача 2

[Официальная документация на русском](https://postgrespro.ru/docs/postgresql/17/backup)

1. Резервное копирование и восстановление.

* Синтаксис команды резервного копирования:

pg_dump [параметр-подключения...] [параметр...] [имя_бд]

[Более подробная справка по синтаксису](https://postgrespro.ru/docs/postgresql/17/app-pgdump)

Пример:

pg_dump -h <ip_addres> -p <port> -U <user-name> -Fc -j 5 db_name > dump_file.dump

-Fc - если PostgreSQL был собран в системе с установленной библиотекой сжатия zlib, пользовательский формат дампа будет сжимать данные при записи в выходной файл. Это позволит получить файлы дампа аналогичного размера gzip, но с дополнительным преимуществом возможности выборочного восстановления таблиц.

-j 5 - выгрузка базы данных в 5 параллельных потоков

* Синтаксис команды восстановления

pg_restore [параметр-подключения...] [параметр...] [имя_файла]

[Более подробная справка по синтаксису](https://postgrespro.ru/docs/postgresql/17/app-pgrestore)

Пример:

pg_restore -d newdb db.dump

-d [имя_бд] - Подключиться к базе данных имя_базы и восстановить данные непосредственно в неё.

2. Автоматизация резервного копирования.

* Можно установить расширение pgAgent для pgAdmin.
* Либо настроить средствами планировщика ОС запуск скрипта резервного копирования.

Пример:
```
#!/bin/bash
export PGPASSWORD="Pass123"
DB_USER="postgres"
DB_NAME="my_db"
BACKUP_DIR="/var/backups/postgres"
LOG_FILE="/var/log/pg_backup.log"

DATE=$(date +%Y-%m-%d_%H-%M-%S)
FILE_NAME="${BACKUP_DIR}/${DB_NAME}_${DATE}.dump"

mkdir -p "$BACKUP_DIR"
echo "[$(date)] Начало бэкапа" >> "$LOG_FILE"

pg_dump -h localhost -U "$DB_USER" -Fc -b -f "$FILE_NAME" "$DB_NAME" 2>> "$LOG_FILE" # 2>> добавляет выводимые ошибки в файл лога

if [ $? -eq 0 ]; then
    echo "[$(date)] Успешно: $FILE_NAME" >> "$LOG_FILE" # Дописываем в конец лога информацию об успешной записи
else
    HOST=$(hostname)
    ERROR_MSG="КРИТИЧЕСКИЙ СБОЙ: Ошибка резервного копирования БД [$DB_NAME] на сервере [$HOST]!"

    echo "[$(date)] $ERROR_MSG" >> "$LOG_FILE"

    # Оповещение через TG API
    curl -s -X POST "https://telegram.org{TG_TOKEN}/sendMessage" \
        -d "chat_id=${TG_CHAT_ID}" \
        -d "text=${ERROR_MSG}" > /dev/null

    exit 1
fi

find "$BACKUP_DIR" -type f -mtime +7 -name "*.dump" -delete # Удаляем бэкапы старше 7 дней

```

## Задача 3

1. Официальный инкрементный бэкап MySQL использует бинарные логи (Binary Logs) и системную утилиту mysqlbinlog:

mysqlbinlog --read-from-remote-server --host=<my_server_ip> --raw --stop-never binlog.000001

--read-from-remote-server — Удаленное чтение логов напрямую с сервера.
--raw — Сохранение файлов в оригинальном бинарном формате.
--stop-never — Непрерывная работа утилиты до ручной остановки.
binlog.000001 — Имя стартового файла для начала копирования.

2. Репликация дает критические преимущества в следующих сценариях:

* Мгновенное восстановление доступности (минимальный RTO).
* Сведение к нулю потери транзакций (минимальный RPO).
* Безопасное распределение тяжелой нагрузки чтения данных.
* Защита системы от физического отказа оборудования.
