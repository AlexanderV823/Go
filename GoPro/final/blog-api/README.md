# REST API для блога на Go (Blog-API)

Промышленное REST API для блога с поддержкой авторизации (JWT), постов, комментариев, структурированного логирования, автоматических миграций и встроенной защиты от DDoS. Построено на архитектуре разделения слоев (Handler -> Service -> Repository -> Database).

## 🚀 Основные возможности

- **Аутентификация**: Регистрация и вход пользователей с генерацией безопасных JWT-токенов.
- **Управление публикациями**: Создание, чтение, пагинация, обновление и удаление постов (удаление и редактирование доступно только автору).
- **Система комментариев**: Написание комментариев к публикациям, обновление и удаление собственных комментариев.
- **Инфраструктурные Middleware**:
  - `Recovery` — автоматический перехват паник для предотвращения падения сервера.
  - `RequestID` — генерация сквозного ID для трассировки цепочки логов.
  - `CORS` — гибкая настройка заголовков для работы с фронтендом.
  - `RateLimiter` — защита API от DDoS и брутфорса (Token Bucket на `sync.Map`).
  - `Logger` — детальные логи запросов с подсчетом байт ответа и времени обработки.
- **База данных**: Автоматические транзакционные миграции схемы данных при старте.

## 💻 Быстрый старт

### 1. Подготовка конфигурации
Перед запуском создайте файл `.env` в корневой папке проекта:

```env
# Настройки сервера Go
SERVER_PORT=8080
SERVER_HOST=0.0.0.0

# Настройки PostgreSQL для Docker и Go
DB_HOST=127.0.0.1
DB_PORT=5432
DB_USER=bloguser
DB_PASSWORD=blogpassword
DB_NAME=blogdb
DB_SSL_MODE=disable

# Безопасность (JWT)
JWT_SECRET=super-secure-random-secret-key-32-chars
JWT_EXPIRY_HOURS=24
```

### 2. Запуск приложения (Выберите один из вариантов)

#### Вариант А. Запуск через `Makefile` (Рекомендуемый)
Если в вашей системе установлена утилита `make`, поднять базу данных в Docker и запустить Go-сервер можно одной автоматизированной командой:
```bash
make dev
```
*Для плавной остановки сервера и очистки контейнеров нажмите `Ctrl+C` в терминале.*

#### Вариант Б. Ручной запуск через Docker Compose и Go (Если нет `make`)
Если команда `make` не найдена в вашей операционной системе, выполните запуск пошагово с помощью стандартных утилит:

1. Поднимите контейнер с базой данных PostgreSQL в фоновом режиме:
   ```bash
   docker-compose up -d postgres
   ```
2. Синхронизируйте и скачайте необходимые Go-зависимости:
   ```bash
   go mod tidy
   ```
3. Запустите API-сервер:
   ```bash
   go run cmd/api/main.go
   ```

При успешном запуске в консоли появятся логи:
```text
Successfully connected to the database
Database migrations applied successfully
Starting HTTP server on 0.0.0.0:8080
```

## 🎯 Спецификация API (Основные эндпоинты)

### Публичные эндпоинты
- `POST /api/register` — Регистрация нового аккаунта.
- `POST /api/login` — Аутентификация (возвращает JWT-токен).
- `GET /api/posts` — Список постов (поддерживает Query-параметры `limit` и `offset`).
- `GET /api/posts/{id}` — Получение поста по его уникальному ID.
- `GET /api/posts/{id}/comments` — Список комментариев к конкретному посту.
- `GET /api/health` — Сервисный эндпоинт проверки работоспособности.

### Защищенные эндпоинты (Требуют заголовок `Authorization: Bearer <token>`)
- `POST /api/posts` — Создание новой публикации.
- `PUT /api/posts/{id}` — Обновление текста/заголовка поста (доступно только автору).
- `DELETE /api/posts/{id}` — Удаление публикации (доступно только автору).
- `POST /api/posts/{id}/comments` — Написание комментария к выбранному посту.
- `PUT /api/comments/{id}` — Редактирование комментария (доступно только автору).
- `DELETE /api/comments/{id}` — Удаление комментария (доступно только автору).

## 🧪 Тестирование и автопроверка эндпоинтов

В корне проекта находится автоматизированный тестовый сценарий `test_api.sh`. Он позволяет в один клик проверить работоспособность и корректность всей цепочки эндпоинтов приложения (от публичных до требующих JWT-авторизации).

### Что делает скрипт:
1. Выполняет **Health Check** проверку сервиса.
2. Автоматически регистрирует нового уникального пользователя.
3. Проводит авторизацию (Login) и **динамически перехватывает выданный JWT-токен**.
4. Используя полученный токен, создает новый пост.
5. Запрашивает публичный список всех публикаций.
6. Пишет комментарий к созданному посту, обновляет его текст и удаляет его.
7. Удаляет созданный на 4-м шаге пост, проверяя права доступа автора.

### Запуск проверки:

Для запуска теста убедитесь, что API-сервер запущен (`make dev` или `make run`), после чего во втором окне терминала выполните:

```bash
# Предоставляем права на исполнение скрипта (нужно сделать один раз)
chmod +x test_api.sh

# Запускаем автоматическое тестирование
./test_api.sh
```

### Пример успешного вывода в консоли:

### Мониторинг через логи:
Параллельно в терминале и в файле `api.log`, кастомный `LoggingMiddleware` отобразит сквозной лог всех 9 входящих вызовов с указанием присвоенного **Request ID**, IP-клиента, HTTP-методов, статус-кодов, размера ответа и точной скорости обработки (duration) каждого запроса.
